# Fahim Pilot and Measurement Protocol

## Objective

Test whether Fahim improves verified understanding and delayed recall for one defined concept—not whether learners like a chatbot.

## Proposed cohort

- 12–20 learners in one age band.
- One teacher/facilitator and one concept with a known misconception pattern.
- Four-week window with informed consent and a documented privacy notice.

## Measures

| Moment | Measure |
|---|---|
| Baseline | Concept question, confidence and short reasoning |
| Immediate post | Parallel question and explanation |
| Delayed recall | Same construct after 7–14 days without hints |
| Transfer | Novel context requiring the same mental model |
| Behavior | Completion, retry count, time, abandonment and facilitator rescue |
| Trust | Citation correctness, unsafe certainty, teacher review rate |
| Economics | AI cost, latency and support time per completed verified-learning cycle |

## Guardrails

- Do not seed or backfill success outcomes.
- Predefine rubric and analysis before looking at results.
- Report denominators, missing data and attrition.
- Treat AI diagnosis as a hypothesis; sample and review errors manually.
- Suppress teacher cohort insights below the privacy threshold.
- Do not publish personal data or learner chat.

## Success criteria

The pilot owner, teacher and evaluator must agree on thresholds before data collection. Example categories—not claimed targets—include learning gain, delayed retention, transfer, completion without rescue, citation quality, median cycle cost and median latency.

## Evidence package

Produce an anonymized protocol, consent record, instrument/rubric, raw-to-summary transformation, failure examples, limitations and a signed teacher observation. Only then should pilot results enter the pitch.
